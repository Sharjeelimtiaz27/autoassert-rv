Background

Two JasperGold engines, two kinds of blind spot

All 68 assertions are already proven on clean Ibex (BEC 2026 AutoTrans paper). The question here is how much each one protects. Two JasperGold apps answer different halves of that question.

Formal Property Verification (FPV)

Can any sequence of input values break this property?

Explores every value on every cycle and returns either a proof or a counterexample trace. Used by AER.

Security Path Verification (SPV)

Which inputs have a path through the logic to this signal?

Traces how the design is connected, without trying values. Used by SAPC.

Bank-vault picture: FPV checks whether any code on the keypad opens the door. SPV checks whether an air duct leads into the vault.

1 · Security RTL Coverage (SRTLC)

JasperGold COI report · 0 new runs

Question: of the RTL that experts call security-relevant, how much does at least one assertion watch?

  1. Every signal named in an NS31A expert property is security-critical.
  2. Map those signals to Ibex. Unmapped signals still count as gaps.
  3. List the RTL lines that drive each security-critical signal.
  4. Read each assertion's cone of influence (COI): all logic that can affect it.
  5. Count the lines that fall inside at least one COI.
SRTLC = security lines inside ∪ COI ───────────────────────────── × 100% all security lines in module

Per assertion: SRTLC_contrib = share of security lines that only this assertion covers.

2 · Assertion Evasion Resistance (AER)

JasperGold FPV + test signal · 10 runs

Question: if a security-critical signal can be flipped at any time, in any pattern, can that cause a violation without the assertion noticing?

  1. Pick a security-critical signal, e.g. mstatus_we.
  2. Add an undriven input, the test signal test_sig.
  3. Wire modified = real ^ test_sig in a wrapper; the RTL is unchanged.
  4. FPV asks: does any test_sig sequence break security property P while assertion A stays silent?
  5. Proven → AER = 1. Counterexample → AER = 0 with the exact evasion trace.

Open issue: P must be a separate reference property. If P is A itself, AER is always 1. See open issues.

3 · Security Assertion Path Coverage (SAPC)

JasperGold SPV · 10 runs

Question: is there a route into a security signal that no assertion watches at all?

  1. For each security-critical signal, ask SPV for every path from a chip input.
  2. Check whether each path lies inside some assertion's cone of influence.
  3. Paths outside every cone are structural blind spots.
SAPC = SPV paths inside some assertion COI ─────────────────────────────── × 100% all SPV paths into security signals

Why both AER and SAPC: AER only tampers with the signal the test signal is attached to. Routes it never touched stay invisible to it.

Prior work: Eslami, Ghasempouri, Pagliarini (ISQED 2022, arXiv 2201.01130) defined an SPV-based security coverage for assertions. SAPC extends our own group's metric; it is not the first SPV metric.

Composite

Assertion Quality Score (AQS)

AQS = (SRTLC_contrib + AER + SAPC_contrib) / 3

Each part lies between 0 and 1 and gets equal weight, giving one ranked score for every assertion.

The test of the score: run the same assertions on the 39-Trojan benchmark, count the Trojans each one detects, and check the correlation with AQS. A strong positive correlation is the paper's central claim: a formal score computed before any Trojan existed predicts real detection.

A · Assertion → weakness

Each assertion is mapped to the CWE weakness it guards and that weakness's CVSS severity, e.g. PMP → CWE-1220. Grounded in NIST CSWP 45 (hardware threat and sensitivity from CWE/CAPEC).

B · Assertion → Trojan category

Each assertion is mapped to the TrustHub categories it addresses: Availability, Covert, Denial of Service, Integrity, Leak, Privilege. After the Trojan stage, the table also shows which categories it actually detected.

Open issues before the definitions are frozen

Fatal if true · SAPC

SAPC may repeat SRTLC

A cone of influence already contains every path feeding a signal. Any assertion that reads mstatus covers every path into it, so SAPC tends to be 100% or 0%.

Fix both teams agree on: count an SPV functional path (input → security signal → the assertion's failure output), not a syntactic cone. Present SAPC as a security-scoped extension of Eslami, Ghasempouri and Pagliarini (2022), whose node coverage was never tested against Trojans.

Major · AER

Property P is undefined, and the mechanism is published

If P is the assertion itself, AER is always 1. The red team found the same XOR free-input model in Chuah et al. (RISC-V Summit Europe 2025 abstract); the blue team could not confirm this, so read the paper. Both teams relate AER to formal mutation coverage (Chockler et al., CAV 2001).

Fix: define P separately (the NS31A reference property or a golden check), make AER graded by the smallest tampering budget that evades the assertion (E12), and credit the prior models openly.

Major · validation

The correlation test is fragile

Small sample (68 assertions, 39 Trojans), mostly 0/1 detection counts, Trojans written by the same group, and refinement re-tested on the same Trojans.

Fix: freeze the Trojans first, use Spearman with confidence intervals and control for module and cone size, add baselines (E10) and a held-out split (E11). Write "TrustHub categories, new Ibex RTL", since TrustHub's own designs are contested.

Major · positioning

No "first" claims survive

Per-assertion SPV ranking (Eslami 2022, SCARF 2024), assertion ranking (Ayalasomayajula HOST 2024), TDER/TPI on Ibex (our ISCAS 2025 paper) and RISC-V Trojan benchmarks already exist.

Claim instead: the combination of FPV evasion and SPV path evidence in one per-assertion score, computed Trojan-free and shown to correlate with detection on an independent benchmark.

Full reports in docs/research/: red_team.md, blue_team.md, literature_survey.md (72 papers), new_metric_ideas.md, and the summary review_summary.md.
